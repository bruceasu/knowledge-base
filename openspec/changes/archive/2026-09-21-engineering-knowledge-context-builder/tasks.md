## 2. Evidence-aware context assembly

- [x] 2.1 Implement target resolution, fixed one-hop evidence-bearing relation expansion, workspace validation, current canonical/derived preference, stale default exclusion, and explicit allowed-stale degradation.
  - Evidence (2026-09-20): package-internal `ContextCandidateResolver` consumes the validated retrieval preparation, resolves the first current canonical target before current derived, and uses stale only when explicitly allowed and no current target exists. It invokes the controlled relation reader exactly once for the resolved stable target ID, accepts only `REFINES`, `DESCRIBES`, `IMPLEMENTS`, and `VERIFIED_BY`, requires at least one evidence item at confidence 0.5 or above, validates the target anchor and relation workspace, and never expands a related endpoint. Current related objects suppress stale alternatives with the same stable object ID; retryable/unverified objects remain excluded. `ContextCandidateResolution` preserves retrieval/relation diagnostics plus explicit stale, evidence, unsupported-relation, missing-object, and workspace omissions for later deterministic ordering and packing.
- [x] 2.2 Implement stable identity/source-location deduplication, evidence aggregation, fixed priority ordering, and selection reasons for target, requirements/design/decisions, symbols, tests, Git evidence, and other related items.
  - Evidence (2026-09-20): package-internal `ContextCandidateOrganizer` groups candidates only when they share a non-empty stable object ID or the complete stable `SourceRef`; names/titles are never identity keys, and bridge candidates merge all transitively connected groups. It selects a deterministic representative, unions contributing retrieval sources, deduplicates and stable-sorts evidence, reports maximum evidence confidence, and emits one `DUPLICATE_MERGED` omission for each non-representative candidate. `SelectedContextCandidate` carries the aggregated provenance and closed selection reason. Final ordering is target, direct requirement/design, code symbol, test, commit/Git evidence, and other direct relation, followed by current canonical/derived/stale preference and a stable object/source key.
- [x] 2.3 Implement budget packing, deterministic source-located fragment truncation, omission records, incomplete diagnostics, and no-LLM/no-inferred-content behavior.
  - Evidence (2026-09-20): package-internal `DefaultContextBuilder` now composes validation/retrieval, target and one-hop relation resolution, candidate organization, and `ContextBudgetPacker` behind the sole public `build` Interface. The packer processes the target first, admits complete fixed-rendering items while they fit, preserves the complete source header and longest UTF-8-byte-bounded Unicode-code-point prefix when truncating, and emits `BUDGET` omissions for every truncated or excluded candidate. If the target header cannot fit, no lower-priority content substitutes for it. Returned totals use `utf8-bytes-v1`; upstream diagnostics and omissions are preserved, and completeness becomes false for source failures or budget loss. Fragments only normalize line endings and retain source text; no summary, inferred content, LLM, tool, transport, write, or retry behavior is present.
