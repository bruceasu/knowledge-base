## 2. JSON normalization and identity

- [x] 2.1 Parse supported Ctags tag records while filtering metadata/progress records and reporting unknown kinds, malformed records, missing fields, encoding errors, and unexpected exits deterministically.
  - Evidence (2026-09-20): stdout is decoded with a reporting UTF-8 decoder and parsed one nonblank JSON line at a time under the strict JSON policy. Records require a nonblank `_type`; only `_type=tag` reaches field parsing, while profile metadata/progress records are ignored. Each bad tag is skipped in encounter order with `MISSING_REQUIRED_FIELD`, `UNKNOWN_KIND`, or `MALFORMED_OUTPUT`, marks the result incomplete, and preserves valid records; invalid UTF-8 and nonzero process exits map separately to `ENCODING_ERROR` and `UNEXPECTED_EXIT` rather than an empty successful result.
- [x] 2.2 Normalize Java class, interface, method, field, and other confirmed kinds into source ranges, language/kind metadata, qualified names, signatures, and core-compatible static-analysis evidence.
  - Evidence (2026-09-20): the fixed Java kind mapping covers annotation, class, enum constant, field, enum, interface, method, package, and record tags. Parsed lines become validated one-based `SymbolSourceRange` values and immutable `ExtractedSymbol` candidates that retain language, kind, simple name, optional signature/scope/scope kind, and normalized relative path. Package-aware qualified-name construction handles top-level and nested/member scopes without duplicating the package prefix, while every candidate carries `EvidenceType.STATIC_ANALYSIS`, an `engineering-workspace` `SourceRef`, and an explicit line or line-range location.
- [x] 2.3 Implement deterministic symbol identity using workspace/path/language/kind/qualified-name/signature and the explicit location-sensitive fallback/diagnostic for incomplete metadata.
  - Evidence (2026-09-20): `SymbolIdentity` is an explicitly Adapter-local key encoded as transparent `ctags-symbol-v1` length-prefixed UTF-8 fields in fixed workspace ID, normalized path, language, kind, qualified-name, and discriminator order. Signed symbols use a `signature:` discriminator, so preceding-line shifts do not change their identity and overload signatures remain distinct. A missing qualified name or method signature instead uses `location:<start>:<end>`, sets `locationSensitive=true`, preserves the candidate, and emits `LOCATION_SENSITIVE_IDENTITY` rather than silently claiming stable identity or merging symbols.
- [x] 2.4 Deduplicate equivalent records and sort candidates deterministically; preserve incomplete/truncated status without persisting results or asserting relations.
  - Evidence (2026-09-20): normalized immutable `ExtractedSymbol` records are collected through a `LinkedHashSet`, so only fully value-equivalent candidates are removed, then sorted by normalized path, start/end position, kind, qualified name, and signature before the observable result limit is applied. Result-budget and stdout-byte truncation retain the bounded parseable candidates with `RESULT_TRUNCATED` or `OUTPUT_TRUNCATED` and `complete=false`; timeout and other terminal failures also return explicit incomplete results rather than a successful empty set. The Adapter returns only in-memory candidates and diagnostics and has no Store/Lucene dependency or relation-writing path.
