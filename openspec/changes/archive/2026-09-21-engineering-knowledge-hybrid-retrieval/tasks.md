## 3. Fusion, freshness, and degradation behavior

- [x] 3.1 Implement candidate validation, workspace confinement, freshness preference, stable identity/source-location deduplication, evidence aggregation, and explicit non-merging of title-only lookalikes.
  - Evidence (2026-09-20): `CandidateFusionPreprocessor` enforces the aggregate ceiling, rejects unconfined external candidates, excludes stale/retryable candidates unless requested, and groups only by a shared core object ID or precise evidence-backed source location. It selects the freshest/provenance-complete representative and de-duplicates evidence while retaining all contributing sources; title/excerpt text is never a merge key. Ctags `SymbolIdentity` is no longer misrepresented as a core object ID, and path-keyed Git evidence is attached only to an already accepted group.
- [x] 3.2 Implement documented tiered fusion: freshness, match category, provenance completeness, source-internal relevance, then stable fallback; never compare raw cross-source scores.
  - Evidence (2026-09-20): `TieredCandidateRanker` deterministically orders fusion-ready groups by current-canonical/current-derived/stale/retryable/unverified freshness, controlled match-category tier, provenance completeness, source-local rank, and object-or-evidence fallback key, then emits bounded public `RetrievalItem` values with machine-testable and human-readable `RankExplanation`. A merged group keeps its freshest representative while separately retaining its best applicable match tier. No raw score exists in the candidate or ranking contracts, so cross-source score comparison is structurally impossible.
- [x] 3.3 Implement bounded per-source execution, partial-result diagnostics, all-source failure behavior, and Git evidence enrichment only for matching source/object paths.
  - Evidence (2026-09-20): `HybridKnowledgeRetriever` validates before source invocation, executes configured internal candidate sources under one five-second deadline, isolates exceptions/timeouts into diagnostics, applies the aggregate and caller result ceilings, and returns remaining items as an explicitly incomplete result when an optional source fails. It invokes the internal `GitEvidenceSource` only after collecting at most 64 paths from matched candidates, so Git cannot create independent results. Empty successful sources remain distinguishable from all-source failure, evidence-required queries exclude unsupported candidates, and retrieval never triggers ingestion or index rebuild.
