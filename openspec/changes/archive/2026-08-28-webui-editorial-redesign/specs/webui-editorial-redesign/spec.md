## ADDED Requirements

### Requirement: 使用页提供聚焦的编辑式界面

系统 SHALL 为知识库使用页提供一致的编辑式视觉层级，使当前工作区、检索/问答、结果阅读和会话管理可被清晰区分，同时保留既有的工作区选择、检索、问答、会话创建、导入与导出能力。

#### Scenario: 用户在桌面端完成检索

- **WHEN** 用户打开使用页并在当前工作区提交检索
- **THEN** 页面以清晰的当前工作区上下文、输入区域和结果区域呈现该流程，且既有检索请求与结果行为不变

#### Scenario: 用户管理会话

- **WHEN** 用户新建、选择、导入或导出会话
- **THEN** 会话控件保持可用，并在视觉上与主内容区明确区分

### Requirement: 管理页以操作分区呈现工作区和内容维护

系统 SHALL 为管理页提供与使用页一致的视觉体系，并将运行状态、工作区登记/修复/移除、内容维护（服务器路径导入、上传文件、同步目录）、索引重建和根目录管理呈现为清晰、独立的操作分区。页面 SHALL 复用既有 HTTP API，且不得改变其后端行为。

#### Scenario: 用户在管理页维护内容

- **WHEN** 用户选择工作区并上传文件或同步目录
- **THEN** 页面显示可识别的操作区、选择状态和操作反馈，且原有上传与同步请求行为不变

#### Scenario: 用户检查并修复工作区

- **WHEN** 用户在管理页刷新状态并对处于异常或需要维护状态的工作区执行修复
- **THEN** 页面显示该工作区的状态和原因，并通过既有 HTTP API 请求修复后刷新状态

#### Scenario: 用户管理根目录与索引

- **WHEN** 用户查看当前工作区的根目录、解除关联某个根目录或请求索引重建
- **THEN** 页面通过既有 HTTP API 完成相应操作并显示反馈

#### Scenario: 用户请求清理根目录

- **WHEN** 用户选择清理根目录而非默认解除关联
- **THEN** 页面要求用户明确确认，并仅在确认后传递既有 HTTP API 所需的清理确认字段

### Requirement: 页面在键盘与窄屏环境保持可操作

系统 SHALL 为可交互控件提供可见焦点状态，并在窄屏下将多栏界面重排为不依赖水平滚动或悬停操作的可读布局。

#### Scenario: 键盘用户定位操作控件

- **WHEN** 用户使用键盘 Tab 在页面的按钮、链接和表单控件之间移动
- **THEN** 当前焦点具有清晰可见的指示，且控件保留其可访问名称

#### Scenario: 用户在窄屏设备打开页面

- **WHEN** 视口宽度不足以容纳桌面多栏布局
- **THEN** 页面将主要区块按阅读顺序重排，输入和操作控件保持可触达

### Requirement: 重设计不增加外部运行时依赖

系统 SHALL 以项目本地静态资源和系统字体完成界面呈现，且不要求远程字体、CDN、前端框架或新的后端 API。

#### Scenario: 离线运行打包后的 WebUI

- **WHEN** 用户在无外网连接的环境中启动带有 WebUI 的程序
- **THEN** 使用页和管理页仍可加载其样式与既有交互功能
