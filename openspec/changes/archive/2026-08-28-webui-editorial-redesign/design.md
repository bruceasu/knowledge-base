## Context

WebUI 的使用页承载工作区切换、检索、问答、会话管理与结果阅读；管理页承载工作区登记和内容维护。现有资源以静态 HTML/CSS/JavaScript 交付，并同时存在开发目录 `webui/` 与 classpath 打包目录 `src/main/resources/webui/`。现有 JavaScript 与 HTTP API 已可完成业务流程，本变更只改善呈现与可用性。

## Goals / Non-Goals

**Goals:**

- 建立克制、清晰、有足够留白和信息密度的编辑式视觉体系。
- 让使用页聚焦当前工作区、检索/问答和会话，让管理操作聚焦在管理页。
- 保持现有元素标识、事件绑定、API 调用与可访问名称兼容。
- 在桌面与窄屏下提供可读、可操作的布局和可见焦点状态。

**Non-Goals:**

- 不改变 HTTP API、会话格式、工作区模型或后端权限语义。
- 不引入设计系统、前端框架、图标库、远程字体或 CDN 资源。
- 不在本变更中实现文档元数据、上传去重或检索排序改造。

## Decisions

### 本地编辑式设计令牌

用 CSS 自定义属性定义纸白背景、深墨文字、冷静蓝色强调色、细边框、圆角和阴影，并使用系统无衬线字体与系统衬线字体形成标题/正文层级。相比下载 Web 字体或完整 UI 框架，这能保证离线场景、包体和首屏加载稳定，同时仍提供一致的视觉语言。

### 保留结构契约，重组视觉容器

保留既有表单控件 ID、会话容器 ID、工作区选择控件及 JavaScript 文件的加载顺序；仅新增语义 class、辅助说明和视觉容器。相比改写前端状态管理，这避免影响已验证的请求、状态更新和会话导入导出逻辑。

### 双页一致、职责明确

使用页使用紧凑的应用头部、上下文侧栏和主阅读/交互区；管理页采用同一视觉令牌，但以工作区和内容维护卡片作为主分区。相比把导入和同步重新放回使用页，这与已确立的“管理操作归管理页”职责一致。

### 管理页直接编排既有管理 API

管理页通过已有 `/api/v1/status`、工作区、索引、根目录和导入端点提供状态观察与管理操作，不复制 CLI 解析逻辑，也不增加服务端 API。页面以“运行状态、工作区、内容、索引与根目录”分区；高影响操作（移除工作区、清理根目录）必须使用原有 HTTP 确认字段，并在浏览器中再次确认。相比仅展示少数导入操作，此方案让用户在 GUI 中获得与当前 CLI 管理命令相近的可见能力，同时仍由服务端维持校验与写入串行化。

### 响应式与可访问性作为基础样式

桌面端保留多栏信息结构；窄屏将侧栏变为顺序内容、控件变为全宽，确保不依赖悬停操作。所有可交互控件保留原生语义，增加可见 `:focus-visible`，并以文字传达状态而非仅靠颜色。

### 单一资源真相与镜像校验

继续以 `webui/` 为编辑源，并将同内容复制到 `src/main/resources/webui/`。静态资源测试检查关键页面和交互契约，避免开发运行和打包运行出现不同界面。

## Risks / Trade-offs

- [静态测试或脚本依赖旧选择器] → 保留现有 ID 和核心 class，并在必要时只更新视觉断言。
- [系统字体在不同设备上略有差异] → 使用可靠的字体栈、尺寸和行高，而不依赖单一字形。
- [CSS 重写影响窄屏布局] → 将响应式规则与桌面规则一起实现，并保留最小宽度和换行约束。
- [管理操作具有破坏性] → 页面明确标明影响范围、默认使用安全的“解除关联”，仅在用户显式输入确认后请求清理。
- [开发资源与 classpath 资源不同步] → 在完成前机械复制并核对两目录内容。

## Migration Plan

1. 更新开发目录中的页面结构和样式，同时保持接口和 DOM 标识兼容。
2. 将资源同步到 classpath 打包目录。
3. 运行已有 WebUI 静态资源测试及 Maven 验证（经用户授权后）。
4. 如需回滚，仅回退静态资源；服务端数据和 API 不受影响。

## Open Questions

- 无。本变更不使用外部设计资源；若后续品牌需要专用字体或插图，应作为具备许可和加载策略的独立变更处理。
