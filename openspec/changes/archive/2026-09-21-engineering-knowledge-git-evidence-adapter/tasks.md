## 2. Evidence normalization and history semantics

- [x] 2.1 Parse commit identity, parent identity, configured audit metadata, and file changes using machine-readable/NUL-safe output rather than human-readable Git text.
  - Evidence (2026-09-20): `GitHistoryReader` reads each exact validated commit with a fixed `show -s --no-show-signature --no-use-mailmap` format whose nine fields are explicitly NUL terminated, strictly UTF-8 decoded, object/timestamp checked, and byte-capped for names, emails, and subject. It reads path facts only through paired `diff-tree -r -z -M -C --name-status/--numstat` calls, compares non-root commits to their first parent and root commits with `--root`, preserves rename/copy endpoints, and rejects malformed, unsupported, duplicate, or mismatched machine records. The resulting `RawGitCommit`/`RawGitFileChange` values remain repository-relative for the next boundary-normalization WorkItem. JDK 21/Maven compile of 161 main sources succeeded with Java release 17.
- [x] 2.2 Normalize add/modify/delete/rename/copy and binary changes to workspace-relative old/new paths; preserve rename/copy endpoints and prevent root escape.
  - Evidence (2026-09-20): `GitEvidenceProjector` lexically validates every NUL-safe Git path, rejects absolute/backslash/dot/parent/empty-segment forms, removes only the canonical repository-to-workspace prefix, and produces normalized `/` workspace-relative evidence locators carrying the exact commit OID. A change with either endpoint outside the registered workspace is omitted with `OUT_OF_WORKSPACE_CHANGE`, so a cross-boundary rename/copy cannot leak an external path. `GitFileChange` now enforces the valid endpoint shape for ADD, MODIFY, DELETE, RENAME, and COPY while retaining the binary flag and both rename/copy endpoints.
- [x] 2.3 Implement documented deterministic commit and per-commit file-change ordering, bounded incomplete results, shallow-history/missing-object diagnostics, and normal empty-history semantics.
  - Evidence (2026-09-20): `LocalGitKnowledgeAdapter.inspect` now composes request validation, the fixed probe, history reader, boundary projector, and one shared execution budget. Selected commits are topologically ordered old-to-new with full OID priority for concurrent roots; projected changes are sorted by normalized path, confirmed kind, and endpoints. Range/change/byte/time limits retain already completed bounded candidates and add `COMMIT_TRUNCATED`, `CHANGE_TRUNCATED`, `OUTPUT_TRUNCATED`, or `TIMEOUT` diagnostics; missing/non-commit/shallow/non-ancestor outcomes remain distinct through the validator/probe codes. A valid selected commit with no in-scope changes is returned normally with an empty change list rather than treated as a tool failure.
- [x] 2.4 Enforce evidence-only output: do not infer engineering relations from commit metadata/diffs and do not persist or mutate Git/SQLite/Lucene state.
  - Evidence (2026-09-20): static package inspection finds only `EvidenceType.VERSION_CONTROL` construction and no `Relation`, relation vocabulary, SQLite, Lucene, repository-write, transport, or persistence dependency. `LocalGitKnowledgeAdapter` returns immutable in-memory candidates; the only process construction is the fixed local Git launcher, and all constructed subcommands are read-only version/repository/object/ancestry/metadata/tree-diff operations.
