# FD-001 持久化与恢复设计

## 所有权与兼容性

个人资料应用由单 workspace 组合根创建和关闭。HTTP 只调用应用接口。已有文档 repository 的 SQLite 数据库位于 `document/data/kb.sqlite`；新表通过 repository 的写连接建立，与已有文档事务共享所有权，不将工程知识 store 与文档 store 当作同一事务。旧表不删除、不改列语义。

新 schema 版本独立记录在 `personal_schema(version)`；新版本启动时先验证版本，超出支持范围拒绝启动。首次增加表前在尚未接受请求时备份数据库，迁移事务失败回滚。备份包括数据库有效内容，不能只复制存在 WAL 写入的主文件。回滚须停止进程并还原整个 workspace 的对应备份，不能只还原元数据。

## 表及约束

- `personal_service`：单行稳定 service_id、游标签名密钥；恢复备份保留身份。
- `personal_documents`：随机外部 id 主键、既有 document_id 唯一映射、collection_id、原始格式、来源类型、原件相对路径、提取状态、时间。现有文档首次映射到默认集合，映射按唯一约束幂等建立。
- `personal_collections`：集合 id 主键及显示名；首版内置默认资料和笔记集合。
- `personal_operations`：operation_id 主键，主体与 idempotency_key 唯一，规范化请求/摘要、预分配外部 id 和受控文件名、state、index_state、受控错误、结果、创建时间。终态不自动清除。
- `personal_imports`：任务 id、预分配外部 id、托管原件路径、格式、state、错误、提取结果和时间；原件保存成功与可查询状态分开。
- `personal_citations`：操作/笔记外部 id、顺序、来源外部 id、版本、位置、保存时标题及来源快照；不保存客户端提供的 URL。

集合不是现有虚拟工程项目，不复用工程项目权限。token 配置绑定稳定主体、scope 和允许集合，所有资源查询先做集合授权。对象不存在与不可访问统一 404。

## 创建笔记状态机

1. 校验请求、引用和权限，补齐默认值后规范化 JSON。保持数组顺序及正文空白，按键排序对象；计算 UTF-8 摘要。
2. 同一个写事务中检查/插入回执，预分配操作 id、资料外部 id 和 UUID 文件名。相同主体/键不同内容返回 409；相同内容返回原操作。只有提交后才能返回 202。
3. 单写队列处理 pending。文件通过受控临时文件加原子发布；文件名来自回执，不来自用户标题。如果文件已存在，检查内容摘要；匹配则继续，不再次分配名称。
4. 文档登记和映射通过确定路径及唯一键恢复；登记成功后记录 succeeded。索引失败记录 index_state=failed，不能把已保存误报为保存失败。
5. 启动时恢复 pending；已终态保持终态。用户删除后保留回执及墓碑，重放不得恢复文件。同主体轮换 token 不改变幂等空间。

不得在既有 `inTransaction` 上盲目嵌套事务。需要复合写时增加 repository 原子操作，由服务层串行协调。文件系统和 SQLite 不能原子提交，以上检查点必须覆盖“文件存在、登记不存在”和“登记存在、回执未终态”。

## 导入与预算

原件先写临时文件，逐块计量 100,000,000 字节，成功原子发布后创建任务；崩溃留下的无引用临时文件启动清理，不删除已接受原件。单 worker 处理持久队列，内存只保留任务 id。拒绝队列溢出时清理未接受上传；不重复创建已接受原件。

ZIP 展开每块计量，最多 500,000,000 字节、2,000 个条目、单文件 100,000,000 字节，压缩比最多 100:1；元数据长度不能替代实际计量。拒绝绝对路径、盘符、父路径逃逸、符号链接与名称冲突，不递归展开嵌套归档。DOCX 的内部 ZIP 同样预检；XML 禁止 DTD/外部实体和外部链接加载。

原件与提取内容分目录保存。HTML 阅读首版显示提取后的纯文本及受保护附件列表，不直接执行原 HTML；原 HTML 可作为下载附件保留。无法准确定位的内容只返回文档级引用。

## 搜索与读取

复用文档检索候选，按授权集合及过滤条件确定可见结果，再截取 limit；不能以先截断未经授权候选冒充完整查询。响应明确 complete/hasMore/freshness。搜索、读取均读取同一版本快照。游标签名包含主体、文档 id、版本、码点偏移及过期时间；重启保持签名密钥，正文变化返回 409。

## 验证边界

实现阶段静态检查每个事务与文件发布断点、路由认证和大小预算。编译只说明类型和依赖可解析；真实异常恢复、代理隔离和 ZIP 样本结果必须在授权运行验收后才能称为验证通过。未实测不允许描述为已可安全公网部署。
