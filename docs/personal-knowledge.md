# 个人知识库使用与升级

知识库与秘书部署在不同主机。知识库保存原件、提取正文和笔记；秘书通过 `/api/v2/secretary` 查询及保存，不打开共享 SQLite/索引。秘书项目代码不在本仓库改动；独立接入契约见 [交接文档](handoffs/personal-secretary-knowledge-handoff.md)。

## 启用

保留现有 `workspace_root`、端口和 LLM 配置。按 `config-example.toml` 的个人模式配置项填写可达 HTTPS origin、秘书凭证文件和代理密钥文件，设置 `personal_knowledge_enabled="true"`。配置只接受数字 loopback 绑定地址；同机 Caddy 负责外部 HTTPS。认证示例、Authelia 账号文件与恢复说明见 [部署目录](../deploy/personal/README.md)。

未启用个人模式时保留原有工具入口，新的个人 API 不注册；默认后端监听也收紧到 loopback。启用后 `/` 指向资料收集页。初次启动会增加个人资料表，不能在没有备份和验证的情况下直接升级唯一生产副本。

## 收集与阅读

- 浏览器上传每请求一个文件；多选时逐个上传。文件内容上限为 100,000,000 字节，multipart 总体另容纳 65,536 字节开销；前后端均检查，以服务端实际读取为准。
- 单实例最多两个并发上传，持久待处理队列最多 128 个任务。满载返回 429 与 Retry-After。`personal_storage_quota_bytes` 限制个人托管目录（原件、正文、临时文件、笔记），0 表示不设逻辑配额；不代表磁盘空间无限。
- 原件保存后异步提取 Markdown/TXT、HTML、文本 PDF、DOCX 或 OneNote HTML ZIP。图片及不支持格式仍保留原件，不能声称正文可搜索。PDF 无正文时报告处理失败，OCR 没有启用。
- ZIP 最多 2,000 项，展开总量 500,000,000 字节，单项 100,000,000 字节，压缩比 100:1；拒绝越界/冲突路径和符号链接，不递归解压嵌套 ZIP。DOCX 内部包也使用这些限制，并将 XML 总量限制为 20 MB。提取正文最多 10,000,000 Java 字符，超过时保留原件并报告失败。
- ZIP 原始资源关系保留在原包；正文汇集 HTML/TXT/Markdown，显示缺失资源及未加载外部链接的诊断。首版阅读页只显示纯文本，附件通过受保护原包下载取回，不渲染主动 HTML 或执行外部内容。
- 页面区分等待处理、可查询、部分可查询、失败和不支持。失败/部分任务可按原任务重试，不新建原件。
- 笔记正文为 Markdown。界面在 sessionStorage 保存待确认请求和原幂等键；超时先对账，不换键重发。保存与索引状态分别显示。不要在共享浏览器会话中保留敏感未完成笔记。

## 新增 HTTP 边界

秘书的五类端点严格以独立交接文档为准，JSON 请求 256 KiB、响应 1 MiB。服务凭证只保存 SHA-256 摘要，配置绑定稳定 subject、scope 与允许集合。首版内置集合 `default`（资料）和 `notes`（笔记），`*` 是操作者可配置的全库授权；请求无法自行扩权。

浏览器路由 `/api/v2/personal/` 提供上传、导入列表/重试、最近资料、读取、原件下载、笔记和创建状态。它们必须经可信代理身份验证；写请求要求精确 Origin 和 `X-KB-CSRF: 1`。旧浏览器业务 API 在个人模式下同样保护，写请求只接受 JSON。秘书路由不依赖浏览器 cookie。

读取游标与主体、资料、版本绑定，15 分钟过期。全文索引候选预算 5,001 个片段，达到预算返回不完整诊断，不假装完整。外部登记文件未经自动同步观察时 freshness 为 unknown；读取核对文件摘要，变化则 409，不混用旧引用与新正文。

## 迁移、备份与回滚

1. 停止知识库服务，确认 workspace 没有其他进程持有，复制完整 workspace 到受保护备份位置，另备份凭证文件和 Authelia 数据/密钥。
2. 升级使用干净构建产物。旧 MCP class 不应从旧 `target/` 混入新包；构建者按项目既有 `mvn clean package` 流程重新生成，本文不表示已执行该构建。
3. 首次启用个人模式，在开始接受 HTTP 前，用 SQLite `VACUUM INTO` 创建 `document/.kb/migration-backups/before-personal-v1-*.sqlite`，再以事务创建 personal schema v1。此 SQLite 备份仅用于迁移诊断，不能替代完整文件/索引备份。
4. schema 版本不兼容或迁移失败时启动失败；不删除原数据。serviceId 与游标签名密钥保存在文档 SQLite 中，恢复时一起恢复。
5. 回滚先停止服务，恢复同一时间点完整 workspace 和旧程序/配置。不要仅还原一张表、单个数据库文件或索引，也不要将两个不同时间点的原件与元数据拼接。

笔记创建回执与引用快照不自动过期。删除笔记不会删除幂等终态，重放不能重新创建。上传临时文件在启动时清理；原件及持久任务是恢复依据。索引可重建，但原件、笔记、回执、引用和身份不可丢失。

## MCP 兼容性变化

MCP 专属启动入口、注册层、SDK 依赖和专属测试已移除。保留应用 facade、检索、trace 和 context 供现有 HTTP 使用。个人资料搜索/读取/保存由秘书契约替代；代码符号等旧 MCP 专属客户端调用没有兼容 shim，需要改用现有工程 HTTP 能力或保留旧版本独立 workspace。

## 验证范围

FD-001 执行了 Java 17 compile-only 检查，没有运行测试、实际代理、用户浏览器、真实资料、跨机联调、断电/崩溃恢复或最终打包。上线前必须单独完成这些运行验证；静态审查不代表公开网络入口已实测安全。
