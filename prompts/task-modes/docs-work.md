# Docs Work

## Scope
- update the nearest relevant docs
- keep docs aligned with the real code, commands, and paths
- avoid broad doc rewrites unless the task asks for them

## Accuracy
- do not claim a command works unless it was verified or clearly marked
  unverified
- use static link, path, terminology, and consistency review by default
- do not run documented commands merely to validate documentation unless the
  user authorizes it
- separate current behavior from planned behavior
- call out migration or rollout notes when behavior changed

## Style
- prefer short concrete instructions
- keep examples copyable
- remove stale steps instead of adding conflicting notes
